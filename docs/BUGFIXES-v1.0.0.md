# v1.0.0：v0.13.0 里发现的错误和改进策略

2026-10-29 通读了 v0.13.0 的全部代码，并逐条做了复现。当时 325 个测试全部通过，下面的问题都是测试没有覆盖到的地方。v1.0.0 把它们全部修好了，每一条都在 `tests/test_v1_fixes.py` 里有回归测试。

“真实误差”的算法：热方程用 Fourier 级数的解析解，对流题用平移一个周期后回到初值这一点，ODE 用 `rtol = 1e-12` 的 Radau 解作参考。

## 1. 数据不光滑时，误差估计偏小，agent 报“成功”但答案不准（严重）

**现象。** 题目没有精确解时，agent 用两套嵌套网格做 Richardson 估计。数据有拐点或跳跃时，这个估计会偏小好几倍，甚至几十倍：

| 题目（都没有精确解，要求 1e-2） | v0.13.0 的结果 | 估计误差 | 真实误差 |
|---|---|---|---|
| 热方程，初值 `Abs(x-0.5)-0.5` | heat.crank_nicolson n=256，成功 | 2.1e-3 | 1.85e-2 |
| 热方程，初值方波 `Heaviside(x-0.3)-Heaviside(x-0.7)` | heat.crank_nicolson n=2048，成功 | 6.9e-3 | **0.525** |
| 对流，初值 `Abs(x-0.5)` | advection.upwind n=512，成功 | 8.4e-3 | 3.2e-2 |

**原因。**
- Richardson 公式里用的是方法声称的阶（CN 是 2）。题目特征分析其实已经发现数据不光滑，把预测阶降成了 1，但这个降阶只用来挑网格，没有用到误差估计上。
- 用实测阶修正估计的代码，只在相邻两次加密的倍数相同时才会生效；可是网格经常一次跳 4 倍或 8 倍，所以修正几乎从来不触发。
- 方波这一题还有一个原因：初值的“最高波数”是按插值误差估的，方波在 n=128 就被当成“看清了”。实际上方波含有任意高频，CN 每步对这些高频几乎不衰减，只是来回振荡。两套网格上的振荡差不多，于是误差估计也很小。

**改进策略。**
- 误差估计改用“方法阶数”和“特征给出的阶数”中较小的那个。
- 实测阶改为由任意两个加密倍数解出来（`agent.observed_rate`，二分法求解），每次加密都会参与修正。
- 数据不光滑时，估计误差必须低于 `tol / 2` 才算达到精度（`ROUGH_SAFETY = 2`）。
- 数据有跳跃（Heaviside、sign、floor、ceiling）时，CN 这类方法的阻尼检查按网格能承载的最高频 k = πn/L 来算。如果直到最细网格高频都衰减不掉，预测工作量记为无穷大，agent 直接跳过这个方法，不去运行它。这条记录在经验里的结果是 `skipped`，不算这个方法失败。
- 修复后，上表三题的真实误差都在要求以内。

## 2. 系数名字写错时被悄悄忽略，按默认值算（严重）

**现象。** 热方程的系数叫 `alpha`。写成 `{"D": 0.01}` 时，agent 自动补上 `alpha = 1`，`D` 没有任何用处，最后报告成功，给出的却是 alpha = 1 时的答案：u(0.5) = 0.0072，正确答案是 0.9518。

**改进策略。** 对已知方程，`EquationBook.complete` 会检查题目里的系数。如果一个系数既不是这个方程的，也没有在源项、初值、边界值、精确解里用到，就报错：“heat 方程没有系数 D（它的系数是：alpha）”。网页上显示为“题目有误”，命令行 `pde-agent solve` 打印同样的提示并退出。大模型理解题目时如果给错了系数名，会被要求改正后重新回答。

另外，没有意义的系数现在也会直接报错：Poisson 方程的 `k = 0`，热方程的 `alpha ≤ 0`（不适定）。以前前者会除以 0，然后报“数值发散”。

## 3. 网页上没法学新方程（中）

**现象。** 网页表单不发送 `equation` 字段，页面上也没有地方填。选“一维反应扩散方程”并勾选学习后，总是报“新方程的写法没法核对：no equation text”。“方程类型”是下拉框，里面也没法填一个新名字。

**改进策略。** 表单增加了“方程”输入框（只有新方程需要填，例如 `u_t = D*u_xx - r*u + f`）。选课程示例时会自动填好，提交时随表单一起发送。“方程类型”改成可以直接输入的框，同时保留已知方程的候选列表。

## 4. 技能的静态检查可以绕过（中）

**现象。** 静态检查允许 `import pde_agent`。可是 `pde_agent.skills` 自己导入了 `subprocess` 和 `os`，于是 `from pde_agent.skills import subprocess` 能通过检查，大模型写的代码就可以运行命令、删除文件、读取 API key。`import pde_agent.skill_api` 也会把整个包绑定成一个名字，从它能找到所有已加载的模块。

**改进策略。**
- 本项目里只放行 `pde_agent.skill_api`，写法限于 `from pde_agent.skill_api import ...`、`from pde_agent import skill_api` 和 `import pde_agent.skill_api as 别名`。
- 每次启动加载技能前都重新做静态检查。以前已经入库、按新规则不合格的技能不会被加载，网页和命令行会提示“静态检查不通过”。
- 静态检查依然不是安全沙箱，`README` 的“安全提示”照旧适用。

## 5. 让大模型给 ODE 学方法时，报错信息误导人（低）

**现象。** `pde-agent learn ode.json` 报“新方程的写法没法核对：unsupported characters”，让人以为是方程写错了。

**改进策略。** 直接说明“常微分方程暂时不支持让大模型学习新方法，只能用内置方法”。

## 6. ODE 自适应方法的误差估计偏小（读代码时推测，复现后确认，中）

**现象。** 自适应方法（RK45、Radau、BDF）里的 `n` 设定的是容差 `rtol = n⁻²`，但误差并不会随容差平滑地缩小，有时停在原地一步，然后才突然下降。例如 Van der Pol μ=1000 用 BDF：要求 1e-4 时估计 1.8e-5，真实 1.3e-4；要求 1e-6 时估计 6.8e-8，真实 1.5e-6。Lotka–Volterra 要求 1e-6 时，真实误差是估计的 30 倍。

**改进策略。** 没有精确解时，自适应方法的估计改为直接用两次结果之差（不再除以 r^p − 1），而且必须连续两次加密都达标才算成功。对这类方法也不再做“加密后误差不再下降”的判断。修复后，在 Van der Pol、Robertson、Lotka–Volterra 三题上，按 1e-3 和 1e-6 两种要求分别测试 BDF、Radau、RK45，全部没有假成功。

## 7. 共享经验没有可信度控制（读代码时推测，中）

**现象。** 从经验中心下载的记录和本机记录同等计数。一个成员（或者一个有 bug 的旧版本）只要上传大量“某方法在 n=4 就成功”，所有人的方法排序和起始网格都会被带偏。

**改进策略。**
- 别人的记录按半个权重计算（`SHARED_WEIGHT = 0.5`）。
- 同一类题目，每个成员只算最近 20 条（`MAX_PER_MEMBER`），一个人不能压过所有人。
- 起始网格优先参考本机的成功记录。
- 下载的记录会保留成员名，用来做上面的分组。

## 8. 同步进度按“第几条”记录（读代码时推测，低）

**现象。** 同步用一个计数记住已上传到第几条。如果本机的 `experience.jsonl` 被删除或清空，新记录要等总数超过原来的计数才会再上传。

**改进策略。** 改为记住最后上传的那条记录的 id。如果这个 id 在本机找不到了，就从头再传一遍，经验中心按 id 去重，不会重复入库。

## 9. Verlet 的工作量少算了一半（读代码时推测，低）

**现象。** Verlet 每步算两次完整的右端项，但只计一次。

**改进策略。** 改为分别计算两半右端项（`ODEProblem.f_half`），每步各算一半。这样实际工作量和计数一致，Verlet 也真的变快了。

## 10. 三维题目会把精确解泄露给求解器？（推测，核实后不成立）

三维时，边界数据直接用精确解本身。但表达式里不能出现 `z`，所以精确解在每个 z = 常数的平面上都一样，z 方向两个面上的边界数据本来就包含了它的全部信息，并没有泄露求解器不该知道的东西。代码没有改，只更正了注释。

## 没有在这一版处理的已知局限

下面三项是功能层面的局限，而不是代码错误，已经排在路线图上：

- 代价模型在隐式方法之间挑不准（路线图第 5 项）。
- 网页里的求解和学来的技能运行时没有硬超时（路线图第 2 项：放进独立进程）。
